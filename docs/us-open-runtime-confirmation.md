# 美股开盘实时择时调度

美股盘中任务从纽约市场 09:30 ET 开始，但不再把“第一封成功邮件”视为当天结束，也不再只回答“上一收盘计划现在能不能买”。

- 主调度从 09:30 ET 开始，并保留 09:35 / 09:45 / 10:00 / 10:30 / 11:00 / 12:00 ET 候选。GitHub Actions 即使延迟启动，也始终使用 runner 实际执行时的纽约时间和最新可验证行情。
- 收盘层负责预测标的未来 1D / 5D / 10D / 20D 的上涨概率、期望收益、相对 SPY Alpha、收益分布、MFE/MAE 和预测可信度；盘中层负责判断当前价格路径是否值得立即执行。
- 盘中状态分为 `现在可以买`、`等更好买点`、`等确认再买`、`今天不买`、`计划失效`、`行情不足`。其中等待/行情不足属于非终态，后续候选会继续复查。
- `等更好买点` 会估计近端出现更优入场价格的概率、预计改善幅度和参考更优价；它不是看空，而是表示等待的期望值高于立即追入。
- `等确认再买` 表示价格可能已经更便宜，但下跌或弱势尚未证明结束；系统会继续等待止跌/重新转强，而不是机械抄底。
- 只有当所有标的都进入 `现在可以买 / 今天不买 / 计划失效` 等终态后，才写入当天终态标记并停止后续自动复查。
- 每次成功运行都会保存最新状态；状态未变化时邮件会自动抑制，状态发生实质变化或长时间未更新时才重新通知，避免重复刷屏。
- 上一收盘的风险边界仍是硬约束：盘中择时可以建议等待更好的价格，但不能绕过止损、计划失效、风险否决或凭空扩大仓位上限。
- 如果任务几乎在 09:30 ET 准点启动而分钟行情尚未准备好，同一次任务会先做短暂 warm-up；数据仍不可验证时发送非执行状态，并保持后续复查资格。
- 预测概率与证据覆盖率是两个独立概念。低历史样本时概率会做先验收缩并标明校准状态，不会把“数据齐全”伪装成“高胜率”。

调度与执行入口：`.github/workflows/01-us-open-confirmation.yml`、`scripts/run_us_open_timing.py`、`scripts/run_us_open_confirmation_safe.py`。
